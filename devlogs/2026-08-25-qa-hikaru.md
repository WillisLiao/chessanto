## What was found and fixed

1. **One PGN-less game poisoned decoding of an entire monthly archive
   (real end-user fetch failure).** chess.com serves bughouse and other
   partner-variant games with no `pgn` key at all (first seen in the 2016/09
   archive, game index 25 of 114; 20 such games in that month alone).
   `ChessComGame.init(from:)` required `pgn` unconditionally, so decoding the
   archive threw `keyNotFound: 'pgn'` and the whole month failed - on the app
   path that surfaces as "chess.com returned data Chessanto didn't understand"
   for any Hikaru-like account that plays variants. Fix in the shared layer:
   `decodeIfPresent ?? ""` with a comment naming why. Downstream,
   `GameLibrary.importPGN` already rejects empty/unparseable PGNs gracefully,
   so import degrades per game instead of per month. Regression test added:
   `missingPGNDoesNotPoisonArchiveDecoding` decodes a two-game response where
   the first has no `pgn` key and asserts both survive with correct fields.
   Packages/ChessComKit: 5 tests (was 4).
